# Аппаратная часть

## Компоненты (ТЗ п.3.1)

* ESP8266 (модуль ESP-12E);
* шестиканальный релейный модуль (активно-низкий, IN1..IN6);
* датчик температуры и влажности DHT22;
* Wi-Fi 2.4 ГГц;
* подключаемые к реле устройства (свет, увлажнитель, кондиционер и т. п.).

## Распиновка (ТЗ п.3.2)

| ESP8266 | GPIO | Назначение |
| --- | --- | --- |
| D1 | GPIO5 | Relay 1 (IN1) |
| D2 | GPIO4 | Relay 2 (IN2) |
| D3 | GPIO0 | Relay 3 (IN3) |
| D4 | GPIO2 | Relay 4 (IN4) |
| D5 | GPIO14 | Relay 5 (IN5) |
| D6 | GPIO12 | Relay 6 (IN6) |
| D7 | GPIO13 | DHT22 DATA |

DHT22:

* VCC → 3.3V;
* GND → GND;
* DATA → D7 (подтяжка 10 кОм к 3.3V, если не встроена в модуль).

Распиновка зафиксирована в `../../firmware/src/src/main.cpp` и **не зависит** от
настроек backend. Соответствие «логическое устройство ↔ физический канал»
настраивается только в backend (ТЗ п.10).

## Питание

* Релейный модуль питается от **внешних 5 В** (VCC), GND общий с ESP8266.
* Не питать 6 реле от пина 3.3V/5V самой ESP — просадки убивают Wi-Fi.
* DHT22 — строго 3.3V.

## Особенности пинов ESP8266

* **D4 (GPIO2)** — bootstrap-пин: не устанавливать высокий уровень в момент
  загрузки. Активно-низкое реле на этом канале будет кратковременно включено
  при старте. Рекомендуем назначать этому каналу нейтральное устройство
  (например, декоративную подсветку) либо использовать модуль с активно-высоким
  входом на этом канале.
* **D3 (GPIO0)** — low при загрузке = режим прошивки. Реле может щёлкнуть
  при старте.
* **D8/D4-подобные** пины здесь не используются.

## Проверка

1. Прошить `firmware/` (`pio run -t upload`, затем `pio device monitor`).
2. Убедиться, что в логе есть `[wifi] connected` и `[ws] connected to backend`.
3. Включить автоматизацию backend или дёрнуть реле из Web UI —
   реле должны щёлкнуть, backend должен получить `ACK` + `STATE`.
4. Поднести тёплый палец к DHT22 — температура в UI должна расти каждые ~5 с.

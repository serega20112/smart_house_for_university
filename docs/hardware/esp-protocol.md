# Протокол Backend ↔ ESP8266 (v4)

## Транспорт

* WebSocket. ESP8266 — **клиент**, backend — **сервер**
  (`ws://<backend-host>:8001/ws/board`; адрес задаётся `BOARD_SOCKET_PORT` и
  `BOARD_SOCKET_PATH`, по умолчанию — порт 8001 и путь `/ws/board`).
* Каждое сообщение — один JSON-объект в текстовом кадре. С обеих сторон кадр строит и
  читает ArduinoJson: на плате — документом на стеке, на сервере — моделью Pydantic.
* Версия протокола и **ключ платы** передаются ESP в первом сообщении `HELLO`
  сразу после установления соединения.
* Backend держит соединения сразу с несколькими платами: сокет каждой платы
  привязан к одному аккаунту, и кадры этого сокета обновляют состояние только
  этого аккаунта.

## Настройка сети

Ни в прошивке, ни в базе нет ни одного сетевого параметра, записанного
человеком: **ни имени сети, ни пароля, ни адреса сервера**. Плата узнаёт всё
это от своего владельца и хранит в своей собственной памяти.

Два пути, оба кончаются в одной точке — в флеш-памяти чипа:

1. **Точка доступа платы.** Плата, которой ещё не настроили сеть, поднимает
   точку доступа `SmartHome-Setup-XXXXXX` (XXXXXX — идентификатор чипа) и
   отдаёт с неё страницу. Владелец подключается к этой точке, открывает
   `http://192.168.4.1/`, вводит имя сети, пароль и адрес сервера, нажимает
   «Сохранить и подключиться». Плата пишет значения в EEPROM, поднимает точку
   доступа, подключается к сети и работает дальше. Точка доступа больше не
   появляется.

   Точка доступа поднимается и сама по себе, безо всякой кнопки: если плата не
   смогла подключиться к сохранённой сети (сеть сменилась, пароль испорчен),
   она поднимает точку доступа снова, и владелец может вписать данные заново.

2. **Команда от сервера.** Владелец меняет сеть платы в интерфейсе, backend
   отправляет `SET_NETWORK`, плата сохраняет значения и переподключается.

Обе команды проходят по одному и тому же пути: значение лежит в EEPROM, а
флеш-память — единственное место, где оно живёт. Backend держит копию настроек
у себя, чтобы показать их в интерфейсе и повторить передачу, если плата
перезагрузилась раньше, чем получила команду.

Пароль сети в интерфейсе не показывается: он уходит только плате.

## Сопряжение без прошивки

Ключ **не хранится в коде**. На первом включении плата генерирует его сама и
сохраняет в EEPROM чипа: `pairing_key` — это постоянная личность платы, и одна и
та же прошивка уходит всем. Перепрошивать плату для привязки не нужно.

Кто-то должен сказать серверу, кому плата принадлежит:

1. Плата подключается с ключом, который она сгенерировала сама. Решает сервер:
   **неизвестный ключ — это плата без владельца**, даже если сама плата считает
   иначе. Поэтому ответ `CLAIM` приходит всегда, независимо от флага `claim` в
   handshake. Это спасает плату, у которой в собственной флешке залипло «я уже
   привязан»: получив `CLAIM`, она сбрасывает этот флаг и спрашивает снова.
2. Backend отвечает кадром `CLAIM` и закрывает соединение: ни одной команды
   устройства не приходит, потому что плата ещё никому не принадлежит.

   ```json
   {"type": "CLAIM", "label": "0A1B2C", "ttl_sec": 120}
   ```

3. Событие `board.announcement_published` уходит всем подключённым интерфейсам, и в
   экране появляется «найдена плата 0A1B2C»:

   ```text
   GET  /api/esp-devices/claims   → [{"claim_token": "K7R2M9QX", "label": "0A1B2C", ...}]
   POST /api/esp-devices/claims   → {"claim_token": "K7R2M9QX", "name": "ESP кухня"}
   ```

4. Ключ платы записывается в БД под этим аккаунтом. Плата тем временем
   переподключается сама (через 5 с) и уже привязана.
5. Backend подтверждает это в каждом handshake кадром `CLAIMED`. Плата записывает
   его в EEPROM, и с этого момента не задаёт лишних вопросов.

Окно сопряжения живёт 120 секунд, и кто успел первым — тот забрал, поэтому чужая
плата, подключённая к вашему аккаунту без вас, не перехватывается.

Зажатая кнопка FLASH при включении питания открывает окно сразу, не дожидаясь
сервера. Это нужно в двух случаях: плату только что распаковали, или её отвязали
в интерфейсе и хотят забрать заново. В остальное время достаточно того, что плата
подключится сама.

Реле для этого не используются: исполнительные органы дома не мигают, чтобы
сообщить о сопряжении. Вся индикация — в serial-мониторе платы и в интерфейсе
того аккаунта, который вошёл.

Если `claim` в `HELLO` равен `false`, а сервер ключ не знает, ответ всё равно
`CLAIM`: решение принимает сервер, а не флаг в памяти платы. Соединение
закрывается кодом `4403` без единой команды устройству.

## Инициализация

После подключения ESP отправляет:

```json
{
  "type": "HELLO",
  "firmware_version": "1.5.0",
  "protocol_version": 4,
  "pairing_key": "<ключ, который плата сгенерировала сама>",
  "label": "0A1B2C",
  "claim": false,
  "relays": [false, false, false, false, false, false],
  "ssid": "Домашняя",
  "provisioned": true
}
```

Поле `ssid` — сеть, в которой плата работает сейчас, а `provisioned` — заведена
ли она вообще. Backend показывает обе сети в интерфейсе: ту, что задана, и ту,
что плата сообщает о себе.

Backend отвечает полным запросом состояния:

```json
{"type": "GET_STATE"}
```

ESP немедленно отправляет `STATE` (см. ниже) — это закрывает требование
синхронизации после восстановления связи.

## Backend → ESP

### SET_RELAY

```json
{"type": "SET_RELAY", "command_id": "c-16f", "channel": 3, "state": true}
```

| Поле | Тип | Описание |
| --- | --- | --- |
| `command_id` | string | Идентификатор команды, возвращается в ACK |
| `channel` | int 1..6 | Физический канал реле (нумерация фиксирована в прошивке) |
| `state` | bool | `true` — включить, `false` — выключить |

ESP обязан ответить `ACK` с тем же `command_id` и затем `STATE`
с обновлённым состоянием всех реле.

### GET_STATE

```json
{"type": "GET_STATE"}
```

ESP отвечает `STATE`.

### SET_NETWORK

```json
{
  "type": "SET_NETWORK",
  "command_id": "c-16f",
  "ssid": "Домашняя",
  "password": "пароль",
  "host": "192.168.1.10",
  "server_port": 8000,
  "socket_port": 8001,
  "socket_path": "/ws/board"
}
```

| Поле | Тип | Описание |
| --- | --- | --- |
| `command_id` | string | Идентификатор команды, возвращается в ACK |
| `ssid` | string | Имя беспроводной сети |
| `password` | string | Пароль сети, пустая строка для открытой сети |
| `host` | string | Числовой адрес сервера |
| `server_port` | int | Порт обычного интерфейса сервера |
| `socket_port` | int | Порт WebSocket-сервера плат на сервере |
| `socket_path` | string | Путь WebSocket-сервера плат на сервере |

Плата записывает значения в EEPROM, отвечает `ACK` с тем же `command_id`,
переходит в новую сеть и переподключается к серверу по новому адресу.

Пароль сети приходит только в этом кадре и ни в одном ответе не появляется.

### CLAIM

```json
{"type": "CLAIM", "label": "0A1B2C", "ttl_sec": 120}
```

Сервер понял плату и ждёт, пока её заберёт кто-то из интерфейса.

### CLAIMED

```json
{"type": "CLAIMED"}
```

Владелец найден. Приходит в каждом успешном handshake: подтверждение намеренно
дублируется, потому что плата узнаёт о привязке не в момент нажатия, а при
следующем подключении. Ответ пишется в EEPROM — после этого плата больше не
просится и не мигает.

## ESP → Backend

### STATE

```json
{
  "type": "STATE",
  "relays": [false, true, false, false, true, false],
  "temperature": 22.4,
  "humidity": 46.2
}
```

* `relays[0..5]` — состояния каналов 1..6 (`true` = включено).
* `temperature` / `humidity` могут отсутствовать, если датчик ещё не дал
  валидных показаний.

Отправляется: по `GET_STATE`, сразу после выполнения `SET_RELAY`,
и периодически (каждые ~5 с).

### SENSOR_DATA

```json
{"type": "SENSOR_DATA", "temperature": 22.4, "humidity": 46.2}
```

Периодические показания DHT22 (без состояния реле).

### ACK

```json
{"type": "ACK", "command_id": "c-16f"}
```

### ERROR

```json
{"type": "ERROR", "code": "BAD_CHANNEL", "message": "channel out of range 1..6"}
```

| Код | Значение |
| --- | --- |
| `BAD_MESSAGE` | кадр не читается как JSON или не несёт поля `type` |
| `BAD_COMMAND` | отсутствующие поля команды |
| `BAD_CHANNEL` | канал вне диапазона 1..6 |
| `UNKNOWN_TYPE` | неподдерживаемый `type` |

## Обработка потери связи

* Backend считает ESP недоступной, если соединение закрыто или нет сообщений
  дольше `BOARD_WATCHDOG_SEC` (двойной период телеметрии). Все устройства
  переходят в `UNAVAILABLE`.
* ESP при потере соединения автоматически переподключается (интервал 3 с)
  и после восстановления отправляет `HELLO` + `STATE`.
